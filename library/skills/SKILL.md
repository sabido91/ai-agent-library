  downstream analysis.

# Evidence Synthesis Engine

Turn raw consumer evidence into structured, auditable evidence.

The purpose of this skill is not to jump directly from transcripts or notes to recommendations.
Its purpose is to establish a reliable evidence layer that downstream skills can use.

Core flow:

Raw Evidence
→ Familiarize
→ Extract
→ Code
→ Pattern
→ Challenge
→ Synthesize
→ Evidence Bank
→ Handoff

---

# 1. Core Principle

Always separate:

1. Evidence
2. Interpretation
3. Hypothesis
4. Recommendation

Do not collapse these layers.

A quote is not an insight.
A repeated comment is not automatically a market truth.
A qualitative frequency is not population incidence.
A plausible interpretation is not validated evidence.

The skill must preserve the chain from original source to synthesized finding.

---

# 2. When to Use

Use this skill when the user provides or refers to:

- interview transcripts
- interview notes
- research summaries
- diary studies
- open-ended survey responses
- ethnographic or observational notes
- qualitative concept-test feedback
- pack / claim / proposition reactions
- consumer workshop outputs
- research debrief notes
- mixed qualitative datasets

Typical requests:

- "Analyse these interviews."
- "What patterns do you see?"
- "Synthesize these transcripts."
- "Build an evidence bank."
- "What did consumers actually say?"
- "Find contradictions and outliers."
- "Extract the strongest findings."
- "Prepare this evidence for JTBD."
- "Prepare this for opportunity mapping."
- "Compare participants."
- "What evidence is strong vs weak?"

---

# 3. When NOT to Use

Do not use this skill as the primary skill when the user mainly wants:

- research planning
- questionnaire design
- interview-guide design
- recruitment planning
- synthetic consumer simulation
- concept ideation
- final value proposition design
- opportunity prioritization
- final innovation gate recommendation
- persona creation from assumptions
- statistical analysis of representative quantitative data

Do not treat synthetic consumers, LLM personas, simulated interviews, or model-generated
responses as real consumer evidence.

If synthetic material is present, classify it explicitly as:

SYNTHETIC SIMULATION — NOT REAL CONSUMER EVIDENCE

and keep it separate from the real evidence base.

---

# 4. Required Inputs

Work with the evidence available.

Where possible, identify:

- business or research decision being informed
- research objective
- target / participant definition
- market
- occasion or context
- source type
- participant IDs
- interview guide or study questions
- relevant stimulus shown to participants
- known sample limitations

Do not block progress unnecessarily.

If the decision or objective is unclear but the user has supplied substantial evidence,
proceed with synthesis and mark:

Decision context: Gap to clarify

If a missing input would materially change interpretation, ask at most 3 focused questions.

---

# 5. Evidence Classification

Every meaningful evidence unit should be classified where useful.

## Evidence Type

- Observed behaviour
- Reported behaviour
- Attitude / opinion
- Motivation
- Emotion
- Barrier / pain
- Desired outcome / gain
- Occasion / context
- Trigger
- Workaround
- Alternative / substitute
- Decision criterion
- Language / metaphor
- Internal/document evidence
- Quantitative evidence
- Synthetic simulation

Do not infer observed behaviour from stated behaviour.

Example:

"I always look for something filling in the afternoon."

Classification:
Reported behaviour / desired outcome

Not:
Observed behaviour

---

# 6. Evidence Strength

Use evidence-strength labels conservatively.

## Strong

Use when:
- supported by multiple independent evidence units;
- grounded in concrete examples or behaviour;
- relevant to the research question;
- little meaningful contradictory evidence exists;
- source quality is adequate.

## Moderate

Use when:
- recurring but incomplete;
- primarily stated rather than behavioural;
- present in a limited subset;
- some ambiguity or contradiction exists.

## Weak Signal

Use when:
- isolated;
- based on one or very few participants;
- highly interpretive;
- poorly contextualized;
- source quality is thin.

## Hypothesis

Use when:
- the interpretation goes beyond what the evidence directly supports;
- causal explanation is inferred;
- future behaviour is inferred;
- market-level relevance is unknown.

Never call a pattern "validated" solely because it appears repeatedly in qualitative interviews.

---

# 7. Phase 1 — Familiarization

Read the evidence before coding it.

For each participant or source, build a concise evidence memo.

## Participant / Source Memo

Include:

- Participant ID / Source ID
- Relevant context
- Main story
- Behaviours
- Attitudes
- Motivations
- Barriers
- Desired outcomes
- Occasions / context
- Workarounds / alternatives
- Strong quotes
- Contradictions
- Surprises
- Data-quality concerns

Distinguish:

What they DO
vs
What they SAY
vs
What the analyst INFERS

Do not force every interview into the same structure if the source does not support it.

---

# 8. Phase 2 — Evidence Extraction

Create atomic evidence units before synthesizing.

Assign an Evidence ID to each important piece of evidence.

Format:

E001
E002
E003
...

Each Evidence ID should contain, where available:

- Evidence ID
- Participant / source
- Evidence type
- Verbatim or faithful paraphrase
- Context
- Occasion
- Relevant topic
- Source location
- Initial analytic note
- Evidence quality

Example:

E014

Participant: P04
Type: Reported behaviour
Context: Afternoon at work
Evidence: Usually skips breakfast and looks for something filling around 16:00.
Initial note: Afternoon hunger may create a functional satiety job.
Strength: Single-source evidence at this stage.

Do not convert the initial note into a finding yet.

---

# 9. Phase 3 — Coding

Code evidence systematically when the dataset is large enough to benefit from coding.

Use one of:

- Lightweight tags
- Full codebook

Default:
Use lightweight tags for small or rapid datasets.
Use a full codebook for larger, complex, repeated, or high-stakes synthesis.

## Suggested Consumer Insight Code Families

Do not force these categories if unsupported.

Possible families:

- Occasion
- Trigger
- Behaviour
- Job / desired progress
- Pain / friction
- Gain / desired outcome
- Motivation
- Emotion
- Decision criterion
- Trade-off
- Current solution
- Substitute
- Workaround
- Barrier
- Price / value
- Channel
- Pack
- Claim
- Sensory
- Brand
- Social influence
- Household dynamics
- Shopper vs consumer
- Language / metaphor

For every code, preserve traceability to Evidence IDs.

---

# 10. Phase 4 — Pattern Detection

Move from codes to meaningful patterns.

A pattern is not simply a frequently mentioned topic.

Look for:

- repeated behaviours
- repeated tensions
- similar decision logic
- shared triggers
- shared workarounds
- shared desired outcomes
- occasion-specific patterns
- recurring trade-offs
- clusters of evidence
- causal hypotheses
- differences between subgroups
- contradictions
- edge cases
- absences

Important:

Frequency supports pattern detection but does not determine importance by itself.

A rare signal can still matter if it represents:

- an extreme user
- an emerging behaviour
- an important unmet need
- a critical barrier
- a high-value occasion
- a potential white space

---

# 11. Phase 5 — Challenge the Pattern

Before promoting a pattern to a finding, actively try to disconfirm it.

For every major pattern ask:

- What evidence supports it?
- What evidence contradicts it?
- Who does not show this pattern?
- Does it depend on occasion?
- Does it depend on target or context?
- Is it behaviour or stated opinion?
- Was the question leading?
- Could this be an artefact of the interview guide?
- Is the pattern caused by repeated probing?
- Is the sample appropriate for this interpretation?
- Are we inferring causality?
- Are we inferring incidence?
- Are we confusing concept appeal with future purchase?
- Are we confusing claimed purchase intent with repeat?
- Are we confusing internal enthusiasm with consumer evidence?

Keep disconfirming evidence visible.

Do not discard outliers just because they complicate the narrative.

---

# 12. Phase 6 — Findings

Promote patterns into findings only when evidence supports doing so.

Each finding should include:

## Finding

Finding ID:
F01, F02, ...

Finding statement:
One clear sentence.

Evidence base:
List supporting Evidence IDs.

Observed in:
Participant/source IDs.

Evidence type:
Behavioural / stated / mixed.

Evidence strength:
Strong / Moderate / Weak Signal.

Supporting evidence:
Short representative examples.

Contradictory evidence:
Relevant Evidence IDs or "None identified".

Variation:
Who or what context differs?

Interpretation:
What the pattern may mean.

Boundary:
What this finding does NOT prove.

Research implication:
What this means for further Consumer Insight work.

Do not automatically produce a commercial recommendation.

---

# 13. Qualitative Frequency Rules

Qualitative counts may be used descriptively inside the sample.

Preferred:

"Observed in 8 of 12 interviews."

Avoid:

"67% of consumers experience this."

Unless the study design genuinely supports population estimation, do not infer population incidence.

Avoid false precision.

Use qualitative frequency to support:
- breadth within the dataset;
- pattern comparison;
- transparency.

Do not use it as market sizing.

---

# 14. Evidence Bank

Build an Evidence Bank for the strongest findings.

For each finding include:

## Anchor Evidence

The richest piece of evidence that illustrates the pattern.

## Echo Evidence

Additional evidence showing that the pattern is not isolated.

## Counter-Evidence

Evidence that limits or contradicts the interpretation.

## Traceability

Include:
- Evidence IDs
- Participant / source IDs
- source location when available

## Evidence Type

Label:
- observed behaviour
- reported behaviour
- attitude
- motivation
- etc.

## Evidence Strength

Strong / Moderate / Weak Signal.

The Evidence Bank is curated.
It is not a dump of every quote.

---

# 15. JTBD / Need-State Preparation

This skill may identify evidence relevant to Jobs To Be Done but should not force final JTBD formulation when evidence is insufficient.

Prepare candidate components:

- Situation / context
- Trigger
- Desired progress
- Functional outcome
- Emotional outcome
- Social outcome
- Pain
- Gain
- Current solution
- Alternative / substitute
- Trade-off
- Occasion

Candidate job:

When [situation / tension],
I want [desired progress],
so that [functional / emotional / social outcome].

Label unvalidated jobs:

Provisional JTBD hypothesis

Do not present a JTBD as validated solely from one quote or analyst interpretation.

---

# 16. Persona / Segment Preparation

Do not automatically generate personas.

First determine whether differences are better explained by:

- occasion
- job
- need state
- behaviour
- attitudes
- life context
- stable consumer archetype

Possible conclusion:

No evidence of stable persona segmentation.

That is a valid output.

If stable clusters are visible, provide:

- clustering dimensions
- participants represented
- supporting Evidence IDs
- key differences
- confidence
- remaining ambiguity

Leave full persona construction to the downstream persona/JTBD skill.

---

# 19. Bias & Quality Gate

Before finalizing, check:

- Have facts and interpretations been separated?
- Have observed and reported behaviours been separated?
- Have qualitative counts been presented only as sample-level observations?
- Have leading-question effects been considered?
- Have contradictions been actively searched?
- Have outliers been retained?
- Have alternative explanations been considered?
- Have causal claims been avoided unless supported?
- Have weak signals been labeled?
- Have synthetic responses been kept separate?
- Can every major finding be traced to original evidence?
- Have unsupported personas or JTBDs been avoided?
- Are recommendations being made too early?
- Are occasion and alternatives/substitutes represented where relevant?
- Are price, channel, pack, sensory or context being ignored where materially relevant?

If any major quality gate fails, correct the synthesis before delivering.

---

# 20. Consumer Insight Principles

For FMCG, beverages, nutrition, snacks, retail and horeca, pay particular attention to:

- occasion
- trigger
- need state
- consumption context
- shopper vs consumer
- current repertoire
- substitutes
- household influence
- convenience
- price/value
- channel
- pack
- sensory expectations
- brand role
- functional benefit
- emotional benefit
- social benefit
- trial barriers
- repeat barriers

Do not assume every project requires all dimensions.

Use only those supported by the decision and evidence.

---

# 21. Closing Rule

The purpose of this skill is to make downstream interpretation safer.

Do not ask:

"What insight can I create from this?"

Ask:

"What does the evidence support, how strong is it, what challenges it, and what can responsibly be inferred from it?"
